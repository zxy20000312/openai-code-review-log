## 1. OpenAiCodeReview.java

### 建议关注点

**① 下游一致性（重要）**
请确认后续流程（git add / commit / push、日志中拼接的仓库文件链接）引用的都是同一个 `fileName` 变量。若其他位置单独拼接了文件名，加扩展名后会造成路径不一致，导致推送或链接 404。

**② 字符编码隐患（存量问题）**

```java
try(FileWriter writer = new FileWriter(newfile)){
```

`FileWriter` 使用**平台默认字符集**，在 Windows 环境下会以 GBK 写出，中文评审内容推到 GitHub 后大概率乱码。建议改为显式 UTF-8：

```java
Files.writeString(newfile.toPath(), content, StandardCharsets.UTF_8);
```

**③ 目录创建健壮性（存量问题）**

```java
if(!dateFolder.exists()){
    dateFolder.mkdir();
}
```

- 建议用 `mkdirs()` 替代 `mkdir()`，避免父目录缺失时创建失败；
- 当前未检查返回值，失败会静默继续，最终在写文件时才抛出难以定位的异常；
- 可直接用 `Files.createDirectories(path)`，幂等且异常语义清晰。

## 2. ApiTest.java —— ❌ 阻断问题

```java
System.out.println(Integer.parseInt("000SHI"));
```

**该修改没有解决任何问题。** `Integer.parseInt` 要求字符串为合法十进制整数（可选正负号 + 数字），`"000SHI"` 中仍含非数字字符 `SHI`，运行时依然抛出：

```
java.lang.NumberFormatException: For input string: "000SHI"
```

加 `"000"` 前缀无济于事——`parseInt` 的失败点在 `S` 而不是前面的零。请确认真实意图后二选一修正：

**意图 A：验证前导零解析**

```java
Assert.assertEquals(123, Integer.parseInt("000123"));
```

**意图 B：验证非法输入抛异常**

```java
@Test(expected = NumberFormatException.class)
public void testParseInvalidInput_thenThrowException() {
    Integer.parseInt("000SHI");
}
```

### 测试规范问题（存量）

- 测试中不应使用 `System.out.println`，必须用断言验证结果，否则测试永远"绿"，失去回归保护意义；
- 方法名 `test` 无语义，建议按「被测行为_预期结果」命名；
- 若这只是本地随手验证的临时代码，不应随功能提交带入仓库。
